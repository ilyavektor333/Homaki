# Запуск GameSite на Railway

Для текущего проекта с SQLite удобнее использовать Railway с постоянным Volume. SQLite-файл сайта будет храниться на Volume в `/data`, поэтому регистрация, роли, активный состав, мероприятия и статистика не будут исчезать после перезапуска контейнера.

## 1. Подготовить GitHub
Создай **приватный** репозиторий на GitHub и загрузите в него содержимое этой папки.

Не публикуй репозиторий открыто: в проекте есть начальная база `seed_database.db` с данными аккаунта системы и текущими данными сайта.

## 2. Создать проект Railway
В Railway выбери `New Project` → `Deploy from GitHub Repo` и укажи этот репозиторий.

## 3. Добавить Volume
В сервисе добавь Volume с mount path:

`/data`

Это обязательно для текущей SQLite-базы.

## 4. Переменные
Можно задать:

`GAME_SITE_DATA_DIR=/data`

`SESSION_COOKIE_SECURE=true`

`PORT` вручную задавать не нужно — Railway передаст его сам.

`SESSION_SECRET` можно не задавать: приложение при первом запуске само создаст секрет и сохранит его на Volume.

## 5. Запуск
В проекте уже есть `Dockerfile`, поэтому Railway сможет собрать контейнер автоматически.

После запуска открой сгенерированный Railway public domain.

## Что происходит при первом запуске
Если `/data/database.db` ещё нет, приложение копирует в него `seed_database.db`. Это переносит текущую начальную базу, включая системный аккаунт Admin.

После этого база живёт на Volume и изменяется уже на сервере.

## Важно для картинок
Каталог `static/game_catalog` входит в Git-репозиторий и разворачивается вместе с кодом. Поэтому после добавления новых картинок на ПК их нужно добавлять в Git и делать новый deploy.
